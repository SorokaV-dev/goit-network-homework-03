# Веб-протоколи та прикладний рівень — домашня робота №3

## 1. HTTP-заголовки та статус-код

Команда:

```bash
curl -I https://example.com
```

Фрагмент відповіді:

```text
HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8
Server: cloudflare
allow: GET, HEAD
```

Статус `200 OK` означає, що сервер успішно обробив запит і повернув ресурс. Заголовок `Location` відсутній, тому редирект не виконувався. Сервер використав HTTP/1.1, що видно в рядку статусу.

## 2. Метод POST

Команда:

```bash
curl -i -X POST https://dummyjson.com/products/add \
  -H 'Content-Type: application/json' \
  -d '{"title":"Network homework note"}'
```

Фрагмент відповіді:

```text
HTTP/1.1 201 Created
Content-Type: application/json; charset=utf-8

{"id":195,"title":"Network homework note"}
```

Статус `201 Created` підтверджує успішне створення ресурсу. GET призначений для читання ресурсу: параметри зазвичай передаються в URL, а відповідь може кешуватися. POST передає дані в тілі запиту та використовується для створення або обробки даних; його відповідь за замовчуванням не вважається кешованою.

## 3. TLS-сертифікат

Команда:

```bash
openssl s_client -connect cloudflare.com:443 -servername cloudflare.com
```

Фрагмент результату:

```text
subject=/CN=cloudflare.com
issuer=/C=US/O=Google Trust Services/CN=WE1
Protocol  : TLSv1.3
Cipher    : AEAD-CHACHA20-POLY1305-SHA256
Verify return code: 0 (ok)
```

Сертифікат `cloudflare.com` виданий центром сертифікації Google Trust Services, проміжний центр — `WE1`. Узгоджено TLS 1.3 і шифр `AEAD-CHACHA20-POLY1305-SHA256`. Код перевірки `0 (ok)` означає, що ланцюжок сертифіката пройшов перевірку.

## 4. Безпека cookies

Команда:

```bash
curl -I https://github.com
```

Фрагмент заголовка:

```text
set-cookie: _gh_sess=…; path=/; HttpOnly; secure; SameSite=Lax
```

Ім'я cookie — `_gh_sess`. Значення не наводжу, бо це сесійний ідентифікатор. Атрибут `HttpOnly` забороняє JavaScript читати cookie, тому зменшує ризик викрадення сесії через XSS. `Secure` дозволяє надсилати cookie лише через HTTPS і захищає від перехоплення через незашифроване HTTP-з'єднання. `SameSite=Lax` обмежує надсилання cookie в частині міжсайтових запитів і знижує ризик CSRF.

## 5. Вибір протоколів для онлайн-біржі

| Сценарій | Протокол | Обґрунтування |
|---|---|---|
| Оновлення графіків у браузері | WebSocket | Підтримує постійне двонапрямлене з'єднання. Сервер може одразу надсилати нові ціни всім підключеним клієнтам без опитування. |
| Білінг ↔ облік акцій | gRPC | Використовує HTTP/2 і компактні повідомлення Protobuf. Це зменшує накладні витрати та дає чіткий контракт між внутрішніми сервісами. |

Для браузерного графіка важлива швидка доставка оновлень у реальному часі, тому підходить WebSocket. Для внутрішніх мікросервісів важливі мала затримка, типізований API й ефективна серіалізація, тому доцільний gRPC.
